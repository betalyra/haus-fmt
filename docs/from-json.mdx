If you've written JSON, you can read haus. Here's one order, translated in four steps.

<Story>

<Step lang="json" label="order.json" code={steps[0]}>

### Looks fine, until it doesn't

`30.30` comes back as `30.3`. `shipped` and `cancelled` can both be `true`. The date is a string. And `null` might mean "no note", "unknown" or "forgot".

</Step>

<Step label="order.haus" code={steps[1]}>

### Same data, less noise

No quotes on keys, comments allowed, a trailing comma is fine. `true` becomes `True`, `null` becomes `None`. Already valid haus.

</Step>

<Step label="order.haus" code={steps[2]}>

### Can it be shipped and cancelled?

Not any more. Three flags become **one variant**, and the time moves inside `Shipped` as a real `Instant`.

</Step>

<Step label="order.haus" code={steps[3]}>

### Nothing left to guess

`Money(30.30, EUR)` keeps every digit and its currency. No note? Leave the field out.

</Step>

## At a glance

| JSON | haus |
|---|---|
| `"key": …` | `key: …` |
| `true`, `false` | `True`, `False` |
| `null` | leave the field out, or `None` / `Some(…)` |
| `{ "type": "email", "address": … }` | `Email(…)` |
| `30.30` (a float, usually) | `30.30` (exact) |
| `"2026-11-08"` | `Date("2026-11-08")` |
| one array per file | a stream: one value per entry |
| no comments | `//` and `/* */` |
| a password is just a string | `Secret String` in the schema keeps it out of logs ([tour](/docs/tours/secrets)) |
| `1794129120000` (milliseconds since 1970) | `Instant("2026-11-08T09:12:00Z")`, or a tagged `Int64` (below) |

## Timestamps as numbers

Many JSON APIs send a time as a number: `"shippedAt": 1794129120000`, milliseconds since 1970. You have two ways to bring it over:

- **Convert it to an `Instant`** where the data enters your system. `Instant("2026-11-08T09:12:00Z")` says what it is, every schema binding checks it, and the conversion is exact.
- **Keep the number** as an `Int64`, and name its unit with a tag of your own, so that no reader takes milliseconds for seconds:

```haus-schema
type EpochMillis = closed < EpochMillis Int64 >

type Order = { id: UInt64, shippedAt: EpochMillis }
```

```haus
{ id: 1042, shippedAt: EpochMillis(1794129120000) }
```

`std/time` has no epoch type on purpose: such a number has no rule beyond the range of an `Int64`, and an `Instant` already holds the same moment. In code, a [codec](/docs/spec#134-codecs) can give either one as your language's time type.
