Your billing service reads its settings from `service.haus`: a port, a database, a key for the payment provider. Two of those values must never show up in a log.

<Story>

<Step label="service.haus" code={steps[0]}>

### A config you can write by hand

Comments say where a value came from, and a trailing comma is fine. The database password and the payments key are the two that matter.

</Step>

<Step lang="ts" label="server.ts" code={steps[1]}>

### Then it ends up in the logs

The service logs its config at startup, which helps when a deploy goes wrong. Now the password and the key are in the logs, and in everything that collects them.

</Step>

<Step lang="haus-schema" label="service.schema.haus" code={steps[2]}>

### Mark them in the schema

`Secret String` accepts exactly what `String` accepts. The file doesn't change, and neither does its hash. Your editor stops showing the values in hovers.

</Step>

<Step lang="ts" label="server.ts" code={steps[3]}>

### Hidden until you ask

A secret decodes to a `Secret`: printing, logging and `JSON.stringify` show `<redacted>`. The value comes out only through **`expose()`**, which is easy to spot in a review.

Encoding writes it in full, since the receiver needs it.

</Step>

<Step label="service.haus" code={steps[4]}>

### Errors don't quote it

The data never says `Secret`; the schema does. So this is an error, and it gives the **field and its type**, never what was found there.

Every error inside a secret works like that, in every language.

</Step>

<Step label="service.haus" code={steps[5]}>

### What it doesn't do

`Secret` keeps a value out of your program's output. It doesn't encrypt anything: the file holds the key in plain text. Keep it out of git and deliver it from a secret manager.

Don't publish a hash of the file either: anyone can hash a guess and compare.

</Step>

</Story>

## Reading a secret

| Language | `Secret String` becomes | Get the value |
|---|---|---|
| TypeScript | `Secret<string>` | `secret.expose()` |
| Effect | `Redacted<string>` | `Redacted.value(secret)` |
| Rust | `haus::Secret<String>` | `secret.expose()`, or `secret.into_inner()` |
| Python | `haus.schema.Secret` | `secret.expose()` |
| Roc | `Secret(Str)` | `secret.expose()` |

The exact rules are in the [specification](/docs/spec#15-decoding-with-a-schema), under "Secrets".
