title: Languages
description: The haus library for each language, what you get from it, and how to install it.
---

Every library reads and writes the same haus. They all run one [conformance suite](https://github.com/betalyra/haus-fmt/tree/main/test-suite) and are fuzzed against the reference parser, so a file that one accepts, the others accept with the same values. They differ in how close they bring the data to your language's own types.

| Language | Install | With a schema, you get |
|---|---|---|
| [TypeScript](/docs/languages/typescript) | `npm install @haus-fmt/haus` | typed values from `h.*` schemas or `.schema.haus` files; any Standard Schema works too |
| [Effect](/docs/languages/effect) | `npm install @haus-fmt/effect effect` | Effect schemas, `Stream`s, errors in the error channel |
| [Rust](/docs/languages/rust) | `cargo add haus-fmt` | structs and enums, generated in `build.rs` |
| [Python](/docs/languages/python) | `pip install haus-fmt` | `dict`s, `tuple`s and `Tagged` values to `match` on |
| [Go](/docs/languages/go) | `go get github.com/betalyra/haus-fmt/go` | checked `haus.Value`s; codecs give your own types |
| [Swift](/docs/languages/swift) | SwiftPM, `github.com/betalyra/haus-fmt` from 0.1.0 | your `Codable` structs and enums |
| [Java and Kotlin](/docs/languages/jvm) | `org.haus-fmt:haus` on Maven Central | your records, sealed interfaces and data classes |
| [Roc](/docs/languages/roc) | `roc/package` in the repository | types and decoders generated by `haus-gen` |
| [Zig and C](/docs/languages/zig) | `zig fetch` a release | a `Decoded` tree in Zig; `libhaus` and `haus.h` for C |

## What every library has

- The parser, with the limits of the spec enforced while parsing, and errors with a line, a column and an [error code](/docs/errors).
- A stream reader that gives values as their commas arrive.
- Writers for the layouts of the spec, the canonical form and SHA-256 hashes. Roc writes the compact and minimised layouts only; Swift hashes where CryptoKit exists.
- The three JSON mappings: schema-based JSON, self-describing JSON and the JSON import.
- Schema files with their imports and `std/time` checked, and decoding errors at their place (`$.lines[0].qty`). Roc reads schema files when it generates code, not at run time.

## Where they differ

- **Profile codecs.** The `iso` and `wgs84` rules of `@haus-fmt/money` and `@haus-fmt/geo` ship as codecs in every library except Swift. Zig has them in its Zig API, not yet in the C ABI. [What haus checks](/docs/checks)
- **The `missing-codec` warning**, when your schema reaches a profiled type without its codec: TypeScript, Rust, Python, Go, Java and Kotlin, and `haus-gen` for Roc.
- **Every error of a file at once**, with positions, as an editor shows them: TypeScript (`checkData`), Rust (`haus-fmt-schema`), Go (`CheckText`), Zig (`decoding.check`) and C (`haus_check_text`). The others stop at the first error.
- **Host types.** What `Int`, `Decimal`, `Maybe` and `Date` become in each language: [Host types in each language](/docs/types#host-types-in-each-language).

The [examples](https://github.com/betalyra/haus-fmt/tree/main/examples) are the same in every language: `quickstart` reads a comment thread with its schema, `order` decodes an order with money, a location and codecs. Each page links to its language's copy.
