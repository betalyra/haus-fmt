# Error codes

The catalogue of the error codes of [§17](README.md#17-error-codes). Every implementation reports these codes, the same in
every binding; a code is never renamed, removed or reused after 1.0, only added. Each code has a page section at
`https://haus-fmt.org/docs/errors#<code>`. The machine-readable source is [`errors.haus`](errors.haus).

"Reported at" is the place of the error (§8): for an error in text, the character its line and column point to; for an error in a value, its path (§15, §16.3). The place is part of the specification, as the code is, except where it is marked *Informative*: the places of errors in schema files and imports are not yet checked across bindings (§8).

|---|---|---|---|---|
| `invalid-utf8` | The input is not valid UTF-8 (§4): a byte sequence that encodes no character, an overlong form or a surrogate. Also an unpaired surrogate in a string of the language (UTF-16) given to a parser instead of bytes. | Where the decoder says, at the first byte that isn't UTF-8; nowhere when it doesn't say. | `version-directive` | The file starts with a `#haus` version directive (§10): it was written for a later, incompatible version of haus. | The `#` (line 1, column 2 after a byte order mark). | `#haus 2 ⏎ { a: 1 }` | Read the file with a version of haus that supports it. |
| `expected-value` | A value is missing: after a key's colon, between commas, or at the start of a file, something else comes where a value must be, also a closing bracket (`[}`, `]`, `1,]`). | `missing-comma` | Two values, fields or top-level values follow each other without a comma between them. | The token found where the comma should be. | `[1 2]` | Add a comma between the two values. |
| `payload-newline` | A tag is followed by `(` or `{` on a later line, or after a comment. | `unexpected-closer` | A closing bracket after a value that doesn't match the open one (`[1}`), or that has no open one (`{ a: 1 }}`). Where a value or key is expected, a closing bracket is `expected-value` or `expected-key`. | The closing bracket. | `[1}` | Close each bracket with its own kind (`{` `}`, `[` `]`, `(` `)`) and remove extra closing brackets. |
| `unclosed-bracket` | A `{`, `[` or `(` is never closed: the input ends first (`[1,`, `Some(`), except right after a key's colon, where it is `expected-value`. | The opening bracket. | `[1, 2` | Add the closing bracket. |
| `null-literal` | `null` is not a value: haus has no null (§1). | The word. | `{ x: null }` | Write `None` (with a `Maybe` type), or leave the field out. |
| `boolean-literal` | `true` and `false` are not values: booleans are the tags `True` and `False` (§1). | The word. | `{ ok: true }` | Write `True` or `False`. |
| `bare-identifier` | A lowercase word where a value should be. Lowercase identifiers are only record keys. | The word. | `[foo]` | Quote it as a string, or start it with a capital letter to make it a tag. |
| `expected-key` | Something that can't be a record key where a key should be, such as a number or a comma. | What stands where the key should be: the token, or the end of the input. | `{ 1: 1 }` | Write a key: a lowercase identifier or a string. |
| `uppercase-key` | A record key starts with a capital letter. Bare keys start with a lowercase letter or `_`; capitalized words are tags. | The key. | `{ Name: 1 }` | Quote the key, or start it with a lowercase letter. |
| `block-string-key` | A block string (`"""`) is used as a record key. | The opening `"""`. | `{ """ ⏎   k ⏎   """: 1 }` | Write the key as a basic string, `"…"`. |
| `missing-colon` | A record key is not followed by `:`. | The token found where the colon should be, or the end of the input. | `{ a 1 }` | Add `:` between the key and its value. |
| `duplicate-key` | A record has the same key twice, after escapes are read (`a` and `"a"` are the same key). Also a JSON object with the same member name twice (§16), and a record built in code with a key twice, rejected when it is built or, at the latest, when it is written, canonicalised or hashed (§11). | The second key, as soon as it is read, before its colon and value: an error in the value is never reached. In JSON, the second name, the same way (§16). Built in code: informative (§11). | `{ a: 1, a: 2 }` | Remove or rename one of the two. |
| `empty-payload` | A tag with empty parentheses, `Tag()`. A tag without arguments is written without them. | The `(`. | `Some()` | Remove the empty parentheses after the tag. |
| `invalid-number` | A number literal that doesn't follow the grammar (§3): a leading zero, a `+`, a `.` without digits on both sides, a misplaced `_`, an uppercase `0X`, digits followed by letters. Also a string that should hold a number literal and doesn't (a `Decimal` in schema-based JSON, §16.3), and a number built in code whose text isn't a literal (`01`, `NaN`), rejected when it is built or, at the latest, when it is written, canonicalised or hashed (§11). | The literal's first character, a sign or a leading `.` included. Built in code: informative (§11). | `007` | Write a decimal number (optional `-`, fraction and exponent) or a hex or binary integer, with `_` only between digits. |
| `unterminated-string` | A string has no closing `"` (in haus or JSON). | The opening quote. | `"abc` | Add the closing quote. A quote inside the string is written `\"`. |
| `string-line-break` | A raw line break inside a `"…"` string. | The line break. | `"a ⏎ b"` | Write the line break as `\n`, or use a `"""` block string. |
| `control-character` | A raw control character (C0, DEL, C1) in a string, block string or comment, where it could change what a terminal shows. A raw tab is allowed in block strings and comments, not in `"…"` strings. Also a raw control character in a JSON string: C0 in any JSON, DEL and C1 in self-describing JSON (§16). | The character. | "a⟨U+0007⟩b": a string with a raw BEL character | Write the character as an escape, `\u{…}`. |
| `bidi-control` | A raw bidirectional control character (U+202A–U+202E, U+2066–U+2069) in a string or comment, or in a self-describing JSON string (§16), where it could reorder how the text is displayed ("Trojan Source", §9). | The character. | // access⟨U+202E⟩ denied: a comment with a raw right-to-left override | Write it as an escape (`\u{…}`) inside a string, or remove it. |
| `invalid-escape` | A backslash followed by a character that doesn't start an escape, or by the end of the input. haus has `\"`, `\\`, `\n`, `\r`, `\t` and `\u{…}`; JSON has its own set. | The backslash. | `"\x41"` | Use one of the escapes of §4, or write `\\` for a backslash. |
| `invalid-unicode-escape` | A `\u` escape that isn't `\u{` 1 to 6 hex digits `}`, or names no Unicode scalar value (a surrogate, or above 10FFFF). In JSON: `\u` not followed by four hex digits. | The backslash. | `"\u0041"` | Write the escape with braces, `\u{…}`, for a character from U+0000 to U+10FFFF other than a surrogate. |
| `block-string-opening` | Text after the opening `"""` of a block string, or the end of the input right after it. The content starts on the next line. | The first character after the opening `"""` and its spaces and tabs, or the end of the input. | `"""text ⏎ """` | Start the content on the line after `"""`. |
| `block-string-closing` | The closing `"""` of a block string has text before it on its line. | The first quote of the closing `"""`. Found before any error in the lines (§4). | `""" ⏎   text"""` | Put the closing `"""` on its own line; its indentation is removed from every line. |
| `block-string-indent` | A line of a block string is indented less than the closing `"""`, whose indentation every line must start with. | Column 1 of the line. Checked before the line's characters (§4). | `""" ⏎   a ⏎  b ⏎   """` | Indent every line at least as far as the closing `"""`. |
| `unterminated-block-string` | A block string has no closing `"""`. | The opening `"""`. Found before any error in the lines (§4). | `""" ⏎   abc` | Add the closing `"""` on its own line. |
| `unterminated-bytes` | A byte string `x"…` has no closing `"`. | The `x` of `x"`. | `x"00` | Add the closing quote. |
| `bytes-not-hex` | A byte string holds something other than hex digits, spaces and tabs, such as a letter after `f`, an escape or a line break, where a byte starts. After a byte's first digit, anything but a second one is `bytes-odd-digits`. | The character. | `x"zz"` | Write two hex digits per byte, on one line. |
| `bytes-odd-digits` | A byte in a byte string has only one hex digit: an odd number of digits, or anything but a second hex digit after the first (a space, a letter after `f`, a line break: `x"az"`). | The lone hex digit. | `x"abc"` | Write each byte as two hex digits. |
| `lone-carriage-return` | A carriage return (CR) not followed by a line feed. Line breaks are LF or CRLF. | The carriage return. | 1,⟨CR⟩2: a carriage return on its own | Save the file with LF or CRLF line endings. |
| `unterminated-comment` | A `/*` comment is never closed. Block comments nest, so each `/*` needs its own `*/`. | The outermost `/*`. | `/* never closed` | Add `*/`, one for each `/*`. |
| `stray-slash` | A `/` that doesn't start a comment. Comments are `//` and `/* */`; haus has no operators. | The `/`. | `{ a: 1 / 2 }` | Write `//` or `/*` for a comment, or remove the `/`. |

## Decoding and encoding

<a id="decoding"></a>Values that don't fit a schema type (§15), and values a program can't encode.

| Code | Meaning | Reported at | Example | Fix |
|---|---|---|---|---|
| `type-mismatch` | A value of another kind than the type accepts: a string for an `Int`, an array for a record, a tag that isn't `True` or `False` for a `Bool`. Decoders never convert between kinds (§15). | The value (§15): `$.items[2]`. For a std/time type, any value that isn't its tag around one string, at the value (`Date(1)` at `$`). | `{ qty: "2" }` with `type Root = { qty: Int }` | Write a value of the expected type; the message says which. |
| `not-an-integer` | A number with a fraction or an exponent where an integer type is expected. `1.0` and `1e3` are not whole numbers by spelling (§15). | The number. | `{ qty: 1.0 }` with `type Root = { qty: Int }` | Write the integer without a fraction or exponent. |
| `out-of-range` | A number outside the type's range: an `Int8` above 127, a negative `UInt32`, a float too large for `Float32`. Never wrapped or clamped. | The number. | `{ age: 300 }` with `type Root = { age: UInt8 }` | Write a value within the range, or use a larger type (`Int`, `Float64`, `Decimal`). |
| `missing-field` | A record lacks a field the type requires. Only fields with `?` may be missing; `None` is not missing. | The record, not the field. | `{ id: 1 }` with `type Root = { id: Int, name: String }` | Add the field, or mark it optional in the schema with `?` after its name. |
| `unknown-field` | A field a closed record doesn't list. Open records ignore such fields (see `unlisted-field`). | The field: `$.extra`. | `{ id: 1, extra: 2 }` with `type Root = closed { id: Int }` | Remove the field, fix its spelling, or add it to the schema. |
| `unknown-tag` | A tag a closed variant doesn't list. Open variants read it as an unknown value (see `unlisted-tag`). | The variant. | `Blue` with `type Root = closed < Red \| Green >` | Use one of the variant's tags, fix the spelling, or add the tag to the schema. |
| `wrong-payload` | A listed tag with another payload than its case says: arguments for a tag without payload, the wrong number of arguments, a positional payload where a record is expected, such as `Circle(1.5)` for the case `Circle { r: Float64 }` (§15). | The variant. | `Some(1, 2)` with `type Root = closed < None \| Some Int >` | Write the payload the schema gives the tag: none, one record, or its positional arguments; the message says which. |
| `invalid-time` | A std/time value whose text the std/time profile rejects: a day that doesn't exist, a missing offset, a lowercase `t` (spec/std/time.md). | The string: `$[0]` for `Date("2026-02-30")`. | `{ on: Date("2026-02-30") }` with `import std/time (Date) ⏎ type Root = { on: Date }` | Write the date or time as the std/time profile says (spec/std/time.md); the message names the type. |
| `invalid-secret` | A value of a `Secret` type that its type doesn't accept, when decoding, or that can't be written, when encoding. The error names the place and the type only, never the value or why it failed (§15). | The secret itself, never a place inside it. | `{ key: 42 }` with `type Root = { key: Secret String }` | Write a value of the secret's type; the value isn't shown, so check it where it comes from. |
| `codec-rejected` | A value its type's schema accepts and a codec rejects (§13.4), such as an amount whose currency isn't in ISO 4217 for the `@haus-fmt/money/iso` profile. At the place of the codec's type. | The place of the codec's type: of the innermost codec that rejects (§13.4). | Money(1, US) decoded with the codec of the profile @haus-fmt/money/iso: US is no ISO 4217 currency | Write a value the codec accepts; the profile's rule (profiles/<name>.md) or the codec's documentation says which. |
| `cannot-encode` | Encoding: a value of the program's language that the type can't write, such as a JavaScript number for an `Int` that expects a bigint, or a string that is no valid `Date`. Building a value in code (§11): a string, key or tag with an unpaired surrogate, which has no UTF-8 form, or, in a binding whose strings are bytes, one that isn't valid UTF-8; or something that is no haus value (an object of another type where a value or a number is expected). Rejected when the value is built or, at the latest, when it is written, canonicalised or hashed. | The place of the value in the type being encoded. Building a value in code: informative (§11). | encode(h.Int, 5): Int is a bigint, 5 is a number | Pass a value of the host type the binding documents for the type. |
| `cyclic-value` | Encoding: a value contains itself, so it has no finite text. | The place of the value that contains itself, or `$`. | const a = { children: [] }; a.children.push(a); encode(Tree, a) | Break the cycle before encoding. |
| `step-budget` | Decoding or encoding took more steps than the input justifies, a sign of a schema doing unbounded work. Bindings MUST bound the work of one decode (§9.8). | `$`: the whole decode or encode. | a hand-written schema that decodes each value many times | Simplify the schema, or raise the step limit if the work is expected. |
| `too-many-nodes` | A value built in code (not parsed) would write more values than the node limit allows (default 64 Mi, §7): its parts share each other so much that it expands when written, counted as writers, the canonical form and hashing write it. | `$`: the value given to the writer, the canonical form or the hash, or to an encoder or decoder with a schema (§15); `$[i]` for the i-th value of a stream written, or of `hashAll`, also when the stream has one value (`$[0]`). From `equals` or `compare`: `$`, and the message says which operand. | a value built in code whose arrays share one another a million times | Build a smaller value, or raise the limit. |

| Code | Meaning | Reported at | Example | Fix |
|---|---|---|---|---|
| `json-syntax` | Text that isn't JSON (RFC 8259): a missing comma or colon, an unquoted name, a trailing comma, a comment, text after the value. | `invalid-tag` | A tag name that isn't `[A-Z][A-Za-z0-9_]*`, or a `"_tag"` that isn't a string: in a `_tag` of either JSON form, in the string of a closed variant whose tags have no payload in schema-based JSON (`"debug"`, §16.3), or in a value built in code (rejected when it is built or, at the latest, when it is written, canonicalised or hashed, §11). | The object that holds the `"_tag"`, or the string of a closed enum (§16.3, "Places").
